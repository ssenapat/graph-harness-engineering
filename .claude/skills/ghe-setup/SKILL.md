# ghe-setup
0. If `ghe/config.yaml` or `ghe/graph.yaml` is missing (the usual case when GHE is installed as a plugin), run `python3 ghe/runner/ghe_tool.py bootstrap` first. It copies the default config and graph (never overwrites an existing file), creates `ghe/runs` and `ghe/memory`, and adds the GHE lines to `.gitignore`. Safe to re-run.
1. Detect the stack from files, then propose `validation.commands` (test, lint, typecheck, build) and `lint.rules` (`[{glob, command with {file}}]`) that match it. Read the manifest first; only propose a command whose script/tool actually exists. An empty list is better than a wrong one. Never suggest another ecosystem's tools (no `npm` in a Python project, no `pytest` in a Node project).
   - **Node / JS / TS** (`package.json`): use the package manager from the lockfile (`pnpm-lock.yaml` → pnpm, `yarn.lock` → yarn, `bun.lockb` → bun, else npm). Propose only scripts present in `scripts`: `test`, `lint`, `typecheck` (or `tsc --noEmit` if `tsconfig.json`), `build`. Lint rule: `*.{js,jsx,ts,tsx}` → `npx eslint {file}`.
   - **Front-end (React/Vue/Svelte, Vite/Next)**: unit/component tests with Vitest (`vitest --run`) or Jest, with Testing Library. Warn if the whole suite is already red (propose a scoped command or ask). If `playwright.config.*` or `@playwright/test` exists, add the e2e command (`npx playwright test`) as optional/UI validation; the Playwright MCP can also drive the running app for visual checks. Do not add Playwright if it is not installed.
   - **Python** (`pyproject.toml`, `pytest.ini`, `requirements.txt`): `uv run pytest` if `uv.lock`/uv config else `python -m pytest`; lint `ruff check .` (if ruff configured) or flake8; typecheck `mypy .`/`pyright` only if configured. Lint rule: `*.py` → `ruff check {file}`. Never propose npm.
   - **Go** (`go.mod`): `go test ./...`, `go vet ./...`, `go build ./...`. **Rust** (`Cargo.toml`): `cargo test`, `cargo clippy`, `cargo build`. **Java/Kotlin**: `mvn test` / `./gradlew test`.
   - **Terraform** (`*.tf`): `terraform fmt -check`, `terraform validate`. **Makefile**: use existing `test`/`lint`/`build` targets.
   - **Monorepo / multi-stack**: propose commands per package, scoped with the right working directory, and ask the user which to include.
2. Confirm with the user (`AskUserQuestion`): tracker `jira` or `local` (default `local`); `deploy_target` default; whether the Reviewer gate is on. If `jira`: ask for the Jira site URL (`https://<org>.atlassian.net`), the project key and optionally the board id, then write them to `jira.*`. Never assume or copy values from another project. Do not store tokens, cloud ids or account ids anywhere: auth is the Atlassian MCP (`/mcp`).
3. Write only those keys (tracker, jira.site/project/board_id, validation, lint, defaults, gates) into `ghe/config.yaml` (preserve the rest and comments).
4. Verify the target's `.gitignore` contains `ghe/`, `.claude/worktrees/` and `.claude/settings.local.json` (add any missing line; never remove existing lines). If `git ls-files ghe` lists tracked files, tell the user to run `git rm -r --cached ghe`; do not run it yourself.
5. Run each validation command once to confirm it works (with a timeout). Report failures instead of leaving broken commands in. If a command fails because of pre-existing breakage (e.g. an already-red test suite), tell the user and offer to drop it, scope it, or keep it; never silently keep a command that always fails, since the Stop hook will block on it.
